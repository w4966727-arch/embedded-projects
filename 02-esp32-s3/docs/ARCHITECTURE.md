## 1. 系统定位

一句话：**ESP32-S3 是神经中枢，云端大模型是大脑，STM32 是手脚，CAM 是眼睛，麦克风是耳朵，喇叭是嘴巴。**

```
                        ┌───────────────────────────────┐
                        │           云端大脑             │
                        │   LLM(思考) + VLM(看图)        │
                        │   ASR(听懂) + TTS(说话) [预留]  │
                        └──────────────┬────────────────┘
                                       │ HTTPS/TLS（唯一的公网出口）
        ┌──────────────┐    UART 帧    ┌────────────────┐   HTTP/JPEG   ┌─────────────┐
        │  STM32F411   │◄─────────────►│   ESP32-S3     │◄──────────────►│  ESP32-CAM  │
        │ 感知/执行节点  │  115200 8N1   │   神经中枢       │   POST /upload │   视觉节点   │
        │ DHT22 温湿度  │              │  (02-esp32-s3)  │               │ (03-esp32-cam)│
        │ 舵机/LED/OLED │              └───┬────────┬────┘               └─────────────┘
        └──────────────┘                  │        │
                                   I2S RX │        │ I2S TX
                                  ┌───────┴─┐    ┌─┴────────┐
                                  │ INMP441 │    │ MAX98357 │
                                  │  耳朵    │    │  嘴巴    │
                                  └─────────┘    └──────────┘
        （所有设备连同一个 WiFi AP：Windows 热点，见 §4）
```

## 2. 角色职责

| 节点 | 角色 | 负责 | 不负责 |
|---|---|---|---|
| ESP32-S3 | 神经中枢 | WiFi/TLS/HTTP、音频 I/O、UART 网关、图片接收、任务调度 | 不做重计算，智能交给云端 |
| STM32F411 | 感知/执行 | DHT22 轮询、舵机 PWM、LED、OLED 显示、本地低延迟控制 | 不碰网络、不碰音频 |
| ESP32-CAM | 视觉 | 拍照、JPEG 编码、HTTP 推送 | 不做图像理解 |
| 云端 | 大脑 | 文字 LLM / 图生文 VLM / (预留) ASR / TTS | 拿不到板上实时数据 |

## 3. 硬件接口总览

| 链路 | 协议 | 电平/速率 | 连接 |
|---|---|---|---|
| STM32 ↔ S3 | UART (8N1) | 3.3V / 115200 | PA9→GPIO18, PA10→GPIO17, GND 共地 |
| INMP441 → S3 | I2S RX | 3.3V | SCK→GPIO4, WS→GPIO5, SD→GPIO6, L/R→GND |
| S3 → MAX98357 | I2S TX | 3.3V~5V | BCLK→GPIO4(共用), LRC→GPIO5(共用), DIN→GPIO7, SD_MODE→3V3 |
| CAM → S3 | WiFi HTTP | 2.4GHz | POST http://192.168.137.100:80/upload |

> I2S 要点：INMP441 与 MAX98357 共享 BCLK/WS（同一时钟域），数据线分开（DIN/DOUT），
> 即"时钟共享、数据独立"。INMP441 输出 24bit 有效数据装载 32bit 槽位（读后 >>8）。
> 采样率统一 16kHz，位深 32bit 槽 / 立体声。

## 4. 网络拓扑（Windows 热点）

```
                 Windows 热点 (AP)
            192.168.137.1 (PC 网关/DHCP)
                      │
        ┌─────────────┴─────────────┐
        │                           │
  ESP32-S3 (STA)              ESP32-CAM (STA)
  静态 IP: 192.168.137.100     DHCP 自动分配
   ← 固定地址，CAM 固件才能写死推送目标 →
```

- S3 用**静态 IP** `192.168.137.100`（网关 192.168.137.1，掩码 255.255.255.0），
  避免 Windows 热点 DHCP 租约变化导致 CAM 找不到 S3。
- CAM 走 DHCP 自动分配，只做客户端，不需要固定地址。
- 坑：Windows 热点可能开启 AP 隔离/防火墙拦截设备互访；联调先 `ping 192.168.137.100` 验证。

## 5. ESP32-S3 固件架构（任务 + 数据流）

ESP32-S3 双核（FreeRTOS SMP）。核0 = 网络/实时侧，核1 = 逻辑侧：

```
                        ┌──────────────── app_main ────────────────┐
                        │ nvs → wifi_init_sta → 各外设init → 建任务  │
                        └──────┬──────────┬──────────┬─────────────┘
                               │          │          │
   ┌─────────────────┐   ┌─────┴─────┐ ┌──┴──────┐ ┌─┴──────────────┐
   │ 核0 实时侧       │   │ 音频采集任务 │ │ 音频播放任务│ │ (WiFi/lwIP 栈)  │
   │ uart_link_task  │   │ I2S RX→    │ │ 环形缓冲→  │ │ 默认跑核0       │
   │ 帧状态机+命令队列 │   │ 环形缓冲    │ │ I2S TX    │ │               │
   └───────┬─────────┘   └─────┬─────┘ └──┬──────┘ └────────────────┘
           │ 队列/事件组        │ 环形缓冲   │ 环形缓冲
   ┌───────┴───────────────────┴───────────┴───────────────────────┐
   │ 核1 逻辑侧                                                     │
   │ ┌────────────────┐ ┌─────────────────┐ ┌───────────────────┐   │
   │ │ main_ctrl_task │ │   llm_task      │ │  cam_server_task  │   │
   │ │ 全局状态机      │ │  阻塞式 HTTPS    │ │  HTTP server       │   │
   │ │ 决策/调度       │ │  ASR/LLM/TTS/VLM│ │  收 JPEG→PSRAM缓冲 │   │
   │ └────────┬───────┘ └────────┬────────┘ └─────────┬─────────┘   │
   └──────────┼──────────────────┼────────────────────┼─────────────┘
              │                  │                    │
              ▼                  ▼                    ▼
         UART下发命令        WAV/图片上传          图片转发云端
```

任务间通信手段（STM32 FreeRTOS 经验平移）：

| 手段 | 用途 |
|---|---|
| 队列 Queue | UART 命令、LLM 结果、HTTP 事件 |
| 环形缓冲 RingBuffer | 音频 PCM 流（麦克风→云端、云端→喇叭） |
| 事件组 EventGroup | WiFi 连接状态、系统就绪标志 |
| 互斥锁 Mutex | 保护共享数据（如 OLED 显示缓冲） |

## 6. 数据链路

### 6.1 遥测上行（STM32 → S3）
```
DHT22 → STM32 轮询(1s) → 组帧(温湿度4字节, CMD 0x01) → USART1 发出
→ S3 uart_rx_task 状态机解析 → 校验 → llm_task 可附带上下文 → 云端
```

### 6.2 控制下行（S3 → STM32）
```
云端回复/用户指令 → S3 main_ctrl_task → 组帧 → UART1 发出
→ STM32 USART1 中断 → xRxQueue → 任务解析 → 舵机/LED/OLED
```

### 6.3 语音链路（预留，M8 实现）
```
INMP441 16kHz采样 → S3环形缓冲 → RMS音量检测(静音断句)
→ 组装WAV头(44B) → HTTPS上传 ASR → 文本
→ LLM → 回复文本 → TTS(云端合成音频流) → 边下边播: 环形缓冲→MAX98357
```
内存账：16kHz×16bit×单声道 = 32KB/秒；3 秒语音 ≈ 100KB，放 PSRAM。
延迟账：ASR ~1s + LLM ~2s + TTS ~1s ≈ 4s 量级。
接口预留：`llm_task` 内留 `asr_upload()` / `tts_play()` 空桩，服务商定了只填函数 + Kconfig。

### 6.4 视觉链路（M6~M7 实现）
```
CAM 拍一帧 JPEG(VGA≈50KB) → POST http://<S3>/upload
→ S3 收图存 PSRAM → base64 编码 → 中转站 VLM "图里有什么？"
→ 文本回复 → (可选) TTS 播报
```
方案选择：**A. CAM 主动推送，S3 被动接收**（S3 统一出口上云，链路最短）。

## 7. 协议设计

### 7.1 UART 帧格式

```
0xAA 0x55 | LEN | CMD | PAYLOAD[0..LEN-1] | SUM
 帧头2字节   长度  命令    负载(≤64B)        异或校验
```

- `LEN` = PAYLOAD 字节数（1 字节，0~64）
- `SUM` = `LEN ^ CMD ^ PAYLOAD[0] ^ ... ^ PAYLOAD[LEN-1]`
- 两侧各自实现同一状态机（S_HEAD1 → S_HEAD2 → S_LEN → S_CMD → S_DATA → S_SUM），解决粘包/半包
- 帧内字节序：大端（MSB 在前）

### 7.2 CMD 表（定案版：小灯/温湿度/OLED/舵机 + 心跳）

| CMD | 方向 | PAYLOAD | 含义 |
|---|---|---|---|
| 0x01 | STM32→S3 | temp_hi, temp_lo, hum_hi, hum_lo (4B) | DHT22 温湿度上报（周期 1s） |
| 0x02 | STM32→S3 | — | 心跳（周期 1s） |
| 0x10 | S3→STM32 | angle (1B, 0~180) | 舵机角度设置 |
| 0x11 | S3→STM32 | 0/1 | 小灯开关 |
| 0x20 | S3→STM32 | UTF-8 文本 (≤60B) | OLED 显示大模型回复 |
| 0x03 | STM32→S3 | 0/1 | 小灯状态上报（预留：状态回执/变化上报） |
| 0x12 | S3→STM32 | — | 小灯状态查询（预留：配合 0x03） |

OLED 适配说明：SSD1306 128×64，6×8 字体最多 21 字符/行 × 4 行可见；
大模型回复需在 S3 侧**截断/分页**，STM32 侧负责滚动显示。

### 7.3 心跳说明（保留）

- **用途**：周期性"我还活着"帧（每 1s 一条，负载 0 字节）。对端超时（如 3s 未收到任何帧）判定链路故障或对端死机。
- **为什么需要**：UART 空闲时线上无任何信号，单靠业务帧无法区分"对方正常但没话说"和"线松了/死机了"。心跳把"链路健康"变成可观测信号。
- **成本**：每 1s 3 字节（帧头2+CMD1），可忽略；实现就是定时器 + 超时计数。
- **决定**：保留，STM32 侧周期发送；S3 侧记录 `last_rx_time`，超时打日志/告警。

### 7.4 HTTP 接口（S3 为服务器）

| 接口 | 方法 | 用途 |
|---|---|---|
| `/upload` | POST | CAM 推 JPEG（body=原始 JPEG；header: `X-Frame-No`, `X-Timestamp`） |
| `/health` | GET | PC 调试用（预留） |

## 9. 内存预算（8MB PSRAM）

| 数据 | 大小 | 存放 | 说明 |
|---|---|---|---|
| JPEG 双缓冲 | 2 × 64KB | PSRAM | CAM 上传的帧 |
| WAV 采集缓冲（5s） | 160KB | PSRAM | 16kHz/16bit/单声道 |
| TTS 播放缓冲 | 32KB | PSRAM | 边下边播 |
| 音频实时环形缓冲 | 4KB | SRAM | 实时路径，DMA 需 SRAM |
| LLM JSON 响应 | 4KB | SRAM | `max_tokens` 控制 |

原则：**SRAM 给实时/低延迟路径，PSRAM 给大块缓冲**（PSRAM 带宽低、延迟高）。
